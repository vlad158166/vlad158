# Опис проєкту та виконаної роботи

## 1. Що це за проєкт

Цей проєкт є бекендом на **Django + Django REST Framework**, який працює з уже існуючою базою даних **PostgreSQL**.

Спочатку завдання формулювалося як навчальний REST API-проєкт для роботи з університетською базою даних, але під час перевірки стало зрозуміло, що у вас уже є **готова заповнена PostgreSQL база** з іншою структурою. Через це бекенд було перероблено так, щоб він працював не з вигаданими моделями, а з **оригінальною базою `auction`**.

Зараз проєкт є REST API для аукціонної системи.

---

## 2. Яку базу даних використовує проєкт

Проєкт підключається до PostgreSQL через файл `.env`.

Поточне підключення:

```env
URL = jdbc:postgresql://localhost:5432/auction
user = postgres
Password = your_password_here
Port = 5432
```

Важливо:

- бекенд тепер працює з базою **`auction`**
- раніше помилково використовувалась база **`postgres`**
- після перевірки було знайдено, що саме в `auction` є реальні таблиці та дані

## 4. Які Django-моделі побудовані на основі оригінальної БД

У файлі [academics/models.py](</d:/OneDrive/Робочий стіл/OBD_7/academics/models.py:1>) створено моделі, які відповідають реальним таблицям PostgreSQL:

- `Buyer`
- `Seller`
- `Operator`
- `Category`
- `Lot`
- `Bid`
- `LotCategory`
- `SellerVerification`

Особливості реалізації:

- моделі мають `managed = False`
- це означає, що Django **не створює і не перебудовує** ці таблиці
- Django ORM працює напряму з уже існуючою структурою вашої БД

Також були правильно відображені зв’язки:

- `Bid -> Buyer`
- `Bid -> Lot`
- `Lot -> Seller`
- `Lot -> Operator`
- `Lot <-> Category` через `lot_category`
- `SellerVerification -> Seller` як `OneToOne`

## 8. У чому була основна помилка і як її виправлено

Початкова помилка була в тому, що бекенд дивився на базу `postgres`, а не на вашу реальну робочу базу `auction`.

Через це спочатку здавалося, що база порожня.

Після додаткової перевірки було:

1. знайдено список усіх баз PostgreSQL на локальному сервері
2. виявлено базу `auction`
3. виконано її інспекцію
4. знайдено реальні таблиці та записи
5. перебудовано Django ORM саме під цю структуру
6. змінено `.env`, щоб проєкт підключався до правильної БД
